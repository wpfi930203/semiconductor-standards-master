## 1. 为什么先做「语种体检」而不是直接蒸馏

蒸馏的第一个动作本应是「整份理解」。但在读第一份文件时就撞上了问题：

**A104F 的文件名是** `JEDEC JESD22-A104F ：2020 Temperature Cycling - 完整英文电子版（15页）_1_15_translate_20240815160915.pdf`
**——正文第一页却是中文**：「电子工程设计发展联合会 / 标准 / 温度循环 / JESD22-A104F」。

文件名里那个 `_translate_` 后缀是唯一的破绽。如果没有先做语种体检，
后续蒸馏会把这份机翻件当成「JEDEC 官方英文原文」直接入库，并给它 A 级可信度
——**这正是本 skill 自己在 v1.0 犯过的错的翻版**（v1.0 的 4 处实质错误全部源于「凭二手中文汇编而未回一手」）。

于是加了一步体检：统计每份语料的中日韩字符占比（CJK%）。

```
93% CJK  jedec/JESD22-B116B.txt      [机翻中文为主]
...
19% CJK  jedec/JESD47L.txt           [英文原文]
 0% CJK  ipc/IPC-7351B.txt           [英文原文]
```

结果：**38 份机翻 / 7 份英文原文**。

### 1.1 文件名与内容语种完全错位

最讽刺的一例：

| 文件名 | 实测正文 |
|---|---|
| `JESD22-B116B引线键合的剪切试验.pdf` | **英文原文**（`Wire Bond Shear Test Method, JESD22-B116B, APRIL 2017`） |
| `JEDEC JESD22-B116B：2017 Wire Bond Shear Test Method - 完整英文电子版（29页）....pdf` | **机翻中文**（「线束剪切试验」「球键」「冶金键」） |

**名字是中文的，内容是英文；名字是英文的，内容是中文。** 完全反了。
→ 结论：**一律以正文自述定级，文件名只作留痕**。

## 2. 引用分层模型的建立

基于上述发现，建立五层模型（这是本次整合的核心产出）：

| 层 | 名称 | 份数 | 可引措辞 | 可引数值 | 规则 |
|---|---|:---:|:---:|:---:|---|
| L1 | 英文原文在库 | 7 | ✅ | ✅ | 可直接引用，标注编号+版本+页/条 |
| L2 | 官方中文译本 | 1 | ✅ | ✅ | 可引用，须注明冲突时以英文版为准 |
| L3 | 机器翻译在库 | 37 | ❌ | ✅ | 只能定位条款号/结构/数值；**术语译名禁止引用** |
| L4 | 扫描件未提取 | 4 | ❌ | ❌ | 内容一律不可引；只能声明「已持有」 |
| L0 | 不在库 | — | ❌ | ❌ | 必须声明无法确认 |

### 2.1 L3 为什么连数值也只给半个 ✅

机翻件的**数值**比**术语**可靠（数字不随翻译变化），但仍有两种风险，实测各抓到一例：

1. **术语硬错**（实测 4 例，全部可复核）：

| 英文原文（L1 语料可证） | 机翻件译法 | 问题 |
|---|---|---|
| Wire Bond Shear Test | 「**线束**剪切试验」 | 线束 = wire harness/cable，与键合线无关 |
| thermosonic (ball) bond | 「**热膜**（球）键」 | 热膜 ≠ 热超声，物理机理完全不同 |
| stitch bond | 「**针线**」 | 标准译法是「针脚焊点」 |
| metallurgical bond | 「冶金键」 | 标准译法是「冶金结合」 |

2. **表格抽取丢符号**（A104 表1，同一份语料内可对证）：

```
原文（13 组条件，业界公知）    机翻件抽取结果
H   -55 / +150          →     H    55 / +150      ← 负号丢失
J     0 / +100          →     J    -0 / +100      ← 0 变成 -0
K     0 / +125          →     K    -0 / +125      ← 0 变成 -0
```

→ 所以 L3 的「可引数值」是**有条件的**：必须先与英文原文或第二来源交叉核对。
审计记录里写明这一点，避免被读成「机翻数值可放心使用」。

### 4.1 关键机制：让纪律「自动生效」而不是「靠自觉」

单纯在 SKILL.md 写规则，Agent 可能不照做。所以把纪律**编进了 CLI 输出**：

```
$ stdq find JESD22-A104F
  ...（原有内容）...
  🟠 本地资料库：L3｜机器翻译在库
     全文语料: references/sources/standards/jedec/JESD22-A104F.txt
     ⚠ 该资料**不可直接引用原文措辞**（机翻件，术语须回英文原文）
     出处: JEDEC JESD22/JEDEC JESD22-A104F ：2020 Temperature Cycling - 完整英文电子版（15页）...
     详情: stdq source JESD22-A104F
```

任何 `find` 的结果都会自动带上「资料在不在库 + 能引用到什么程度」。
用户问「A104 要做多少次」时，模型看到的就不只是条件表，而是**「这是机翻件，措辞不可引」的即时警示**。

`stdq source <不在库的编号>` 直接返回 **rc=1 + 明确的「无法确认」提示**，
从工程上堵住「凭记忆作答」的路径。

## 5. 交叉验证：新资料证实了旧结论

整合不能只是堆文件，得能验证既有内容。**找到一处精确吻合的交叉验证**：

skill 原有 MM-2 断言：「**证明 10ppm/90% 需约 23 万样本**」。
该数字原本来源不明（属需自查项）。现在用 L1 一手数据反推：

```
JESD47L Table 4（0 观测失效 / 100 FPM / 60% CL）→ 需 9,163 件
60% CL 的 χ²/2 = 0.9163（与表内标注的 0.92 吻合）
90% CL 的 χ²/2 = 2.3026
换算比 = 2.3026 / 0.9163 = 2.513
→ 100 FPM @ 90% CL = 9,163 × 2.513 = 23,026 件
→  10 FPM @ 90% CL = 230,261 件   ← 与 MM-2 的「约 23 万」吻合
```

两重意义：
1. **MM-2 的数字是对的**（此前只有断言，现在有一手数据支撑）；
2. **L1 定级是对的**（如果 JESD47L 也被误当机翻件降级，这次验证就做不成）。

同时发现一处**需要标注意外的差异**：JESD47L 用 **60% 置信度**评估 ELFR，
而 AQG 324 Annex I.C 用 **CL 80% 下界**。**两者不是同一体系，不可混用** ——
已写入 §6.6 作为显式警告。
